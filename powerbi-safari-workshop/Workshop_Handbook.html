The brief

Twiga Trails Safaris is a fictional tour operator based in Nairobi. It sells 18 safari packages across Kenya, Tanzania, Uganda and Rwanda, from 3-day budget camping at the Mara to a 12-day honeymoon. Guests book directly on the website, through online travel agencies (OTAs), through overseas tour operators, or as corporate groups.

The CEO is tired of emailed Excel files that never agree with each other. You're the new data analyst, and your job is to deliver one trusted report that answers these questions:

  1. How much revenue and gross profit are we making, and how fast are we growing year on year?
  2. Are we hitting the monthly revenue targets set by finance?
  3. When do guests actually travel, and how is that different from when they book? (Great Migration season vs. the long rains.)
  4. Which sales channels make money, and which ones get cancelled the most?
  5. Which packages and parks drive the business? Is the new Samburu & Laikipia package (launched July 2024) working?
  6. Where do our guests come from, and how does each regional sales manager's patch perform?
  7. How happy are guests (average rating and NPS), and where do we disappoint them?
What you'll hand in
  • A .pbix file with a clean star-schema model, 21 measures and 5 report pages.
  • The report published to a Power BI Service workspace with row-level security and scheduled refresh.
  • A 5-minute presentation of three insights, each backed by a visual from your report.

All the numbers in this handbook come from the real files. Whenever you see a green Checkpoint box, compare your report against it. If your numbers are different, fix that before you move on, because every later step depends on it.

Business rules

These are the rules finance agreed on. Everyone builds with the same definitions, so everyone gets the same numbers.

  • Net amount for a booking = (Adults + 0.5 × Children) × UnitPriceUSD × (1 − DiscountPct). Children pay half price.
  • Net revenue counts every booking that isn't Cancelled. Revenue is recognised on the booking date.
  • Tour cost = every traveller (adults and children) × the package's CostPerPaxUSD.
  • Commission = net amount × the agent's CommissionPct. Direct bookings pay 0%.
  • Gross profit = net revenue − tour cost − commission.
  • NPS = % promoters (score 9–10) − % detractors (score 0–6), shown as a number from −100 to 100.
  • A blank discount means no discount. A blank AgentID in the 2023 file means AG00 (Direct – Website).
Module 0140 min

Get data

Before you load anything, create a parameter for the data folder. Later, when the files move to SharePoint or someone else opens your report, you'll only need to change one value.

  1. Home → Transform data opens Power Query. Then go to Manage Parameters → New. Name it DataFolder, type Text, and set the value to your data path with a trailing backslash, e.g. C:\Workshop\twiga-trails\data\.
  2. Bookings: go to New Source → More → Folder, browse to data\Bookings, then choose Combine & Transform Data. Power BI creates some helper queries; leave them alone. Rename the result to Bookings.
  3. Customers: go to New Source → Excel workbook, pick Customers.xlsx, and tick the Customers sheet. Don't worry about the ugly first rows yet.
  4. Everything else: go to New Source → Text/CSV and load Packages, Parks, Agents, Regions, Reviews and Targets.
  5. Open each query's Source step in the Advanced Editor and replace the hard-coded path with DataFolder & "Packages.csv" (and so on).
Why a folder source?

Finance sends a new bookings file every six months. With a folder source, adding a new year means dropping the file into the folder and clicking Refresh. You'll prove this in Module 8.

Facilitator note — common first-hour problems
  • "DataFormat.Error: couldn't convert to Number" on DiscountPct. The learner's locale uses a comma as the decimal separator. Fix it with the regional setting above, or with Change Type → Using Locale → English (United States).
  • The folder combine picked up a stray file (e.g. ~$Bookings.xlsx or a .DS_Store file from Mac zips). The M code in Module 2 filters to .csv only.
  • If someone is badly stuck, get them to paste the full Bookings query from Module 2 into New Source → Blank Query → Advanced Editor.
Module 0260 min

Clean in Power Query

There are six traps hidden in the data. Try to find each one yourself with View → Column quality, Column distribution and Column profile (set profiling to "based on entire data set" in the status bar) before you read the fix.

TrapWhereFix in the UI
1 · Duplicate rowsBookings 2024Select BookingID → Remove Rows → Remove Duplicates
2 · Messy statusBookingsFormat → Trim, Format → Capitalize Each Word, then Replace Values "Canceled" → "Cancelled"
3 · Blank discountsBookingsReplace Values null → 0
4 · Blank AgentIDBookings 2023Replace Values null → AG00
5 · Title rowsCustomers.xlsxRemove Top Rows (2) → Use First Row as Headers
6 · 46 country spellingsCustomers.xlsxTrim, then Replace Values for each variant

Bookings — full query

Build this step by step in the UI, then open the Advanced Editor and compare. This version also adds three columns you'll need later: Pax, NetAmountUSD and LeadTimeDays.

Power Query MBookings
let
    Source   = Folder.Files(DataFolder & "Bookings"),
    CsvOnly  = Table.SelectRows(Source, each Text.Lower([Extension]) = ".csv"),
    Parsed   = Table.AddColumn(CsvOnly, "Data", each Table.PromoteHeaders(
                   Csv.Document([Content], [Delimiter = ",", Encoding = 65001, QuoteStyle = QuoteStyle.Csv]),
                   [PromoteAllScalars = true])),
    Kept     = Table.SelectColumns(Parsed, {"Name", "Data"}),
    Expanded = Table.ExpandTableColumn(Kept, "Data",
                   {"BookingID", "BookingDate", "TravelStartDate", "CustomerID", "PackageID", "AgentID",
                    "Adults", "Children", "UnitPriceUSD", "DiscountPct", "Status", "PaymentMethod"}),
    Renamed  = Table.RenameColumns(Expanded, {{"Name", "SourceFile"}}),
    Typed    = Table.TransformColumnTypes(Renamed, {
                   {"BookingDate", type date}, {"TravelStartDate", type date},
                   {"Adults", Int64.Type}, {"Children", Int64.Type},
                   {"UnitPriceUSD", type number}, {"DiscountPct", type number}}, "en-US"),

    // Trap 1 — the 2024 file was exported twice for 37 bookings
    Deduped  = Table.Distinct(Typed, {"BookingID"}),

    // Trap 2 — "completed", "COMPLETED", "Completed ", "Canceled"
    StatusTidy = Table.TransformColumns(Deduped, {{"Status", each Text.Proper(Text.Trim(_)), type text}}),
    StatusFix  = Table.ReplaceValue(StatusTidy, "Canceled", "Cancelled", Replacer.ReplaceValue, {"Status"}),

    // Traps 3 & 4 — blanks that mean something
    DiscountFix = Table.ReplaceValue(StatusFix, null, 0, Replacer.ReplaceValue, {"DiscountPct"}),
    AgentFix    = Table.TransformColumns(DiscountFix,
                      {{"AgentID", each if _ = null or _ = "" then "AG00" else _, type text}}),

    // Helper columns for the model
    AddPax  = Table.AddColumn(AgentFix, "Pax", each [Adults] + [Children], Int64.Type),
    AddNet  = Table.AddColumn(AddPax, "NetAmountUSD",
                  each ([Adults] + 0.5 * [Children]) * [UnitPriceUSD] * (1 - [DiscountPct]), type number),
    AddLead = Table.AddColumn(AddNet, "LeadTimeDays",
                  each Duration.Days([TravelStartDate] - [BookingDate]), Int64.Type)
in
    AddLead

Customers — full query

Power Query MCustomers
let
    Source    = Excel.Workbook(File.Contents(DataFolder & "Customers.xlsx"), null, true),
    Sheet     = Source{[Item = "Customers", Kind = "Sheet"]}[Data],

    // Trap 5 — a title line and a blank row sit above the real header
    NoTitle   = Table.Skip(Sheet, 2),
    Headers   = Table.PromoteHeaders(NoTitle, [PromoteAllScalars = true]),
    Typed     = Table.TransformColumnTypes(Headers, {
                    {"CustomerID", type text}, {"FirstName", type text}, {"LastName", type text},
                    {"Country", type text}, {"Segment", type text}, {"AgeBand", type text},
                    {"JoinDate", type date}}),

    // Trap 6 — 46 spellings of 17 countries
    Trimmed   = Table.TransformColumns(Typed, {{"Country", Text.Trim, type text}}),
    Fixes     = {
        {"USA", "United States"}, {"U.S.A.", "United States"}, {"usa", "United States"},
        {"United States of America", "United States"},
        {"UK", "United Kingdom"}, {"U.K.", "United Kingdom"}, {"Great Britain", "United Kingdom"},
        {"UAE", "United Arab Emirates"},
        {"The Netherlands", "Netherlands"}, {"Holland", "Netherlands"},
        {"germany", "Germany"}, {"Deutschland", "Germany"}
    },
    // Apply each {old, new} pair in turn — same as 12 "Replace Values" steps
    Cleaned   = List.Accumulate(Fixes, Trimmed,
                    (tbl, pair) => Table.ReplaceValue(tbl, pair{0}, pair{1}, Replacer.ReplaceValue, {"Country"})),
    FullName  = Table.AddColumn(Cleaned, "FullName", each [FirstName] & " " & [LastName], type text)
in
    FullName

Categories — a tiny dimension

Targets are set by month × category, but category only appears in Packages, where it isn't unique. Right-click Packages → Reference, keep only Category, Remove Duplicates, and rename the query to Categories. Add a sort column too:

Power Query MCustom column on Categories
= Table.AddColumn(#"Removed Duplicates", "CategoryOrder",
      each if [Category] = "Budget" then 1 else if [Category] = "Mid-Range" then 2 else 3, Int64.Type)

Finally, untick Enable load on the helper queries that Folder combine created, and rename every step so a colleague can read it (Deduped, not Removed Duplicates1). Then click Close & Apply.

Trap inside the trap

Use Remove Duplicates on BookingID, not on every column. Here the double-exported rows are exact copies. But in real life a re-export often has a changed status or a trailing space, so a whole-row check lets it through and revenue gets counted twice. Check the row count after every cleaning step.

Date table

Time intelligence functions need a continuous calendar. Go to Modeling → New table and paste the code below. The Season column follows the East African safari calendar.

DAXCalculated table
Date =
ADDCOLUMNS (
    CALENDAR ( DATE ( 2023, 1, 1 ), DATE ( 2026, 12, 31 ) ),
    "Year",       YEAR ( [Date] ),
    "Month No",   MONTH ( [Date] ),
    "Month",      FORMAT ( [Date], "mmm" ),
    "Quarter",    "Q" & QUARTER ( [Date] ),
    "Year-Month", FORMAT ( [Date], "yyyy-mm" ),
    "Season",
        SWITCH (
            TRUE (),
            MONTH ( [Date] ) IN { 7, 8, 9, 10 }, "Migration peak",
            MONTH ( [Date] ) IN { 12, 1 },       "Festive peak",
            MONTH ( [Date] ) IN { 4, 5 },        "Long rains",
            "Shoulder"
        )
)

Then: Table tools → Mark as date table (column Date), and sort Month by Month No.

Don't relate Reviews[ReviewDate] to Date

If you did, Date could reach Reviews by two paths (directly, and through Bookings). Power BI calls this ambiguity and will quietly make one of the links inactive. Here, reviews are analysed by the booking they belong to.

A (Blank) region in your slicer?

That means a country in Customers has no match in Regions, so trap 6 isn't fully fixed. Build a table of Customers[Country] where Regions[SalesRegion] is blank to find the culprit.

Tidy up: hide every ID and foreign-key column from report view, set Parks[Latitude]/[Longitude] data categories, format CommissionPct and DiscountPct as percentages, and create an empty table called _Measures (Enter data) to keep all your measures in one place.

Module 0465 + 45 min

Write the DAX

Build these in order, because later measures reuse earlier ones. After each group, drop the measures into a card or a table by Year and check them against the checkpoint.

Part 1 — Core measures

DAX_Measures
-- Volume
Bookings            = COUNTROWS ( Bookings )
Cancelled Bookings  = CALCULATE ( [Bookings], Bookings[Status] = "Cancelled" )
Cancellation Rate   = DIVIDE ( [Cancelled Bookings], [Bookings] )
Travellers          = CALCULATE ( SUM ( Bookings[Pax] ), Bookings[Status] <> "Cancelled" )

-- Money
Net Revenue         = CALCULATE ( SUM ( Bookings[NetAmountUSD] ), Bookings[Status] <> "Cancelled" )

Tour Cost =
CALCULATE (
    SUMX ( Bookings, Bookings[Pax] * RELATED ( Packages[CostPerPaxUSD] ) ),
    Bookings[Status] <> "Cancelled"
)

Commission =
CALCULATE (
    SUMX ( Bookings, Bookings[NetAmountUSD] * RELATED ( Agents[CommissionPct] ) ),
    Bookings[Status] <> "Cancelled"
)

Gross Profit        = [Net Revenue] - [Tour Cost] - [Commission]
Gross Margin %      = DIVIDE ( [Gross Profit], [Net Revenue] )
Avg Booking Value   = DIVIDE ( [Net Revenue], [Bookings] - [Cancelled Bookings] )
Avg Lead Time (days)= AVERAGE ( Bookings[LeadTimeDays] )
Explain it to your neighbour

Why does Tour Cost need SUMX and RELATED, when Net Revenue only needs SUM? (Hint: the cost per traveller lives in a different table, and it has to be multiplied row by row before it's added up.)

Part 2 — Time, targets, travel date, guests

DAX_Measures
-- Time intelligence (needs the marked Date table)
Revenue LY          = CALCULATE ( [Net Revenue], SAMEPERIODLASTYEAR ( 'Date'[Date] ) )
Revenue YoY %       = DIVIDE ( [Net Revenue] - [Revenue LY], [Revenue LY] )
Revenue YTD         = TOTALYTD ( [Net Revenue], 'Date'[Date] )
Revenue Rolling 3M  =
    CALCULATE ( [Net Revenue], DATESINPERIOD ( 'Date'[Date], MAX ( 'Date'[Date] ), -3, MONTH ) )

-- Switch on the inactive relationship: when do guests actually travel?
Revenue by Travel Date =
    CALCULATE ( [Net Revenue], USERELATIONSHIP ( Bookings[TravelStartDate], 'Date'[Date] ) )

-- Targets (month x category grain)
Revenue Target      = SUM ( Targets[TargetRevenueUSD] )
Target Variance %   = DIVIDE ( [Net Revenue] - [Revenue Target], [Revenue Target] )

-- Guest experience
Avg Rating          = AVERAGE ( Reviews[Rating] )
NPS =
VAR Responses  = COUNTROWS ( Reviews )
VAR Promoters  = CALCULATE ( COUNTROWS ( Reviews ), Reviews[NPSScore] >= 9 )
VAR Detractors = CALCULATE ( COUNTROWS ( Reviews ), Reviews[NPSScore] <= 6 )
RETURN
    DIVIDE ( Promoters - Detractors, Responses ) * 100

-- Ranking
Package Rank        = RANKX ( ALL ( Packages[PackageName] ), [Net Revenue] )

Targets at day level look wrong

Targets are stored on the first day of each month. On a daily axis, the whole month's target shows up on the 1st. Only show target measures at month level or above. If you want to go further, return BLANK() when ISINSCOPE('Date'[Date]).

Module 0945 min

Present insights

In teams of 2–3, choose three findings. For each one, show the visual, say what it means for the business, and recommend an action. You have 5 minutes, and no slides: present straight from your report.

Investigation prompts

  • The OTA problem. OTA bookings are cancelled about twice as often as direct ones, and they carry the highest commission. What is an OTA booking really worth?
  • Book in May, fly in August. Compare booking-date and travel-date revenue by month. What does this mean for cash flow and marketing timing?
  • The August dip. Average rating falls for trips in August. Is it the crowds at Mara river crossings? Which packages suffer most?
  • A new star. The Samburu & Laikipia Private Conservancy package launched in July 2024. How fast did it climb the rankings, and did it take sales away from other packages?
  • Budget safaris. They're popular with travellers, but what share of gross profit do they bring in? Should Twiga keep them?
  • 2026 outlook. Using H1 2026 against the 2026 targets, will the company hit its annual number?
